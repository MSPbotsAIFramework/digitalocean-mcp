[must-fix] `src/digitalocean_mcp/tools/kubernetes.py:259-280` (`digitalocean_kubernetes_delete_cluster`, `mode="selective"`) — the `load_balancer_ids`/`volume_ids`/`volume_snapshot_ids` lists are sent as comma-joined **query parameters** (`params["load_balancers"] = ",".join(load_balancer_ids)`, etc., then `client.request("DELETE", ..., params=params)`), but DigitalOcean's own public OpenAPI spec for `DELETE /v2/kubernetes/clusters/{cluster_id}/destroy_with_associated_resources/selective` (`kubernetes_destroy_associatedResourcesSelective`, referencing `associated_kubernetes_resources.yml#/destroy_associated_kubernetes_resources`) takes `load_balancers`/`volumes`/`volume_snapshots` as a **JSON request body** (arrays of ids), not query parameters — confirmed against `github.com/digitalocean/openapi`, the same spec this ticket's own design (`docs/tickets/PRD-21344.md` § Current state) cites as its contract source. Against the real API this means `mode="selective"` sends an effectively empty body: DigitalOcean will either ignore the caller's id lists (so the tool silently fails its documented "destroy exactly the listed ids" contract, AC9) or reject the call because none of the three optional body fields were supplied. The matching test, `tests/kubernetes/test_tools.py::test_delete_cluster_selective_with_ids:364-382`, enshrines the same wrong assumption (`assert captured["params"] == {"volumes": "v1"}`) so it passes without exercising the real contract — this is why TC9 shows "pass" in Self-test despite the bug; TC23 (the one manual case that would have caught it against a real account) is correctly marked "blocked — needs a real vendor account" and wasn't run. Fix: build a JSON body (`{"volumes": [...], "load_balancers": [...], "volume_snapshots": [...]}`, arrays not comma-joined strings) and pass it via `json_body=`, not `params=`; update the mocked test to assert on the request body instead of query params.

Everything else reviewed clean: credential handling only from `X-DigitalOcean-Api-Token` via the shared `contextvars` middleware (SOP's three iron rules), covered by `tests/test_middleware.py::test_concurrent_requests_do_not_leak_credentials_across_tenants_kubernetes`; error envelope and code vocabulary match the design and the shared `errors.py` exactly (`kubernetes_client.py:979-1021`); retry/backoff on 429/5xx honouring `Retry-After`, bounded budget (AC19, `kubernetes_client.py:893-931`, `tests/kubernetes/test_client.py`); every destructive tool (`upgrade_cluster`, `delete_cluster`, `delete_node_pool`, `delete_node`) requires an explicit resource id and, for `delete_cluster`, an explicit `mode` with no default; `get_kubeconfig`/`get_credentials` never truncate/log the secret payload (asserted by `test_get_kubeconfig_never_logged`/`test_get_credentials_never_logged`); `list_clusters` pagination (default 50, hard cap 200) and the separate lean `_trim_cluster_summary` to stay under the SOP's 20,000-char response bound are both tested; module layout deviates from the design's assumed `kubernetes/` subpackage to the flat `kubernetes_client.py` + `tools/kubernetes*.py` layout the two sibling tickets had already landed by the time this dev leg ran — documented in Self-test as a no-behavior-change implementation detail, consistent with the design's own fallback instruction; README's "MSPbots Connector" section is unchanged/byte-exact and the new Kubernetes tool table lists all 16 tools; no Chinese in any file this ticket touches; `uv run pytest` 88 passed / 0 regressions, local smoke test clean (`/health` 200, missing-header 401, `tools/list` 38 total / 16 `digitalocean_kubernetes_*`); 20/26 test cases pass with real mocked-upstream evidence, 6 correctly deferred as needing a real DigitalOcean account (not a blocker per `mcp-track.md` §3).
