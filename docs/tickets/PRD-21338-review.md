### Findings

1. [must-fix] src/digitalocean_mcp/client.py (whole file — no logging anywhere in `src/`) — The tech design's "Non-functional / Observability" section (docs/tickets/PRD-21338.md §Tech design) states: "structured logs include ticket-relevant fields (tool name, DigitalOcean operation, app/deployment id when present, outcome, latency) and explicitly never include the token header value or full response bodies." This is also a mandatory SOP requirement (`vendor-mcp-development-sop.md` §6 "日志与可观测性": "用结构化日志... 记录：工具名、入参摘要（脱敏）、你的 API 路径与状态码、耗时、错误 code", and the §14 delivery checklist "日志与敏感信息" row "结构化日志带 request-id"). `grep -rn "log\|Log" src/` (excluding the unrelated `get_logs` DigitalOcean tool) finds zero uses of Python's `logging` module or any structured logger anywhere in `src/digitalocean_mcp/` — `client.py`, `middleware.py`, `tools/_shared.py`, and `server.py` have no logging calls at all. Once this connector is live on INT, there is no way to see which tool was called, what DigitalOcean API path/status it hit, how long it took, or what error code it failed with — the design's own stated non-functional requirement is not implemented, and the Self-test section does not flag this as a known/deliberate gap (it is presented as done). Fix: add a structured logger (e.g. stdlib `logging` with a JSON/key=value formatter) that emits one record per outbound DigitalOcean call with request-id/tool name/path/status/latency/error code, verify it never logs the `Authorization` header or `X-DigitalOcean-Api-Token` value or raw response bodies, and note the addition in Self-test.

Everything else reviewed clean: credential handling only from `X-DigitalOcean-Api-Token` via `contextvars`, reset in `finally` (SOP's three iron rules) — verified in `middleware.py:38-66` and the concurrency test `tests/test_middleware.py::test_concurrent_requests_do_not_cross_contaminate_credentials`; error envelope and code vocabulary match the design exactly (`errors.py`, `client.py:111-143`); destructive tools (`delete_app`, `restart_app`, `cancel_deployment`, rollback `commit`/`revert`) all require an explicit resource id, no name lookup or bulk variant; `README.md`'s MSPbots Connector section is byte-identical to the current `vendor-mcp-development/reference/readme-connector-section.md` (verified independently, not just via the repo's own fixture-based test) and sits before the Header table per SOP §0.5; no Chinese anywhere in the repo; pagination/size-cap rules (`clamp_limit`, `bounded_dumps`) match SOP §2.5; 17/20 test cases pass with real mocked-upstream evidence, 3 correctly deferred as needing a real DigitalOcean account (not a blocker per `mcp-track.md` §3); dependencies (`fastmcp`/`mcp[cli]`, `httpx`, `pydantic`, `pydantic-settings`, `uvicorn`, `starlette`) match what the tech design's "Reuse & cleanup" section named, no undisclosed additions; Dockerfile is multi-stage, non-root in production, has `curl`, `EXPOSE 8080`, `HEALTHCHECK`; `uv.lock` committed.

### Fixes

1. [finding 1] Added `src/digitalocean_mcp/telemetry.py` (new): a stdlib-`logging`-based `log_event(event, **fields)` that serializes each call to one JSON line, tagged with a per-request id held in a `ContextVar` (`set_request_id`/`get_request_id`/`reset_request_id`, same reset-in-`finally` discipline as the existing credential `ContextVar`). Wired it into the three files the review named plus `server.py`'s only entry point:
   - `middleware.py` — binds a fresh `uuid4().hex` request-id around every `/mcp` request (reset in `finally`, independent of whether the credential header is present); logs a `missing_credential_header` warning (path only, no header values) on the 401 path, so that case is observable too.
   - `client.py` — `DigitalOceanClient.request()` logs one `digitalocean_api_call` event per outbound attempt (method, path, `status_code` or a transport-level `error_code` for timeouts/network errors, `attempt`, `retrying`, `latency_ms`); never logs the `Authorization` header or the response body.
   - `tools/_shared.py` — `tool_guard` (already wraps all 18 tools) logs one `tool_call` event per invocation (`tool`, redacted `args`, `outcome`, `error_code`, `duration_ms`). Redaction (`_redact_args`): short scalars (str/int/float/bool, capped at 200 chars) are kept as-is (ids, limits, flags — not secrets); anything else (dict/list — e.g. an app `spec`, which can carry `SECRET`-type env vars) is collapsed to its type name (`"<dict>"`), so a tenant secret embedded in a tool argument can never reach the logs.
   - `__main__.py` — added `logging.basicConfig(level=logging.INFO, format="%(message)s")` so the JSON lines actually reach stdout at runtime (uvicorn's own loggers configure their own handlers and are unaffected).
   Commit: `febdb14` (`dev/PRD-21338`).
