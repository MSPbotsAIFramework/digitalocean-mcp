[must-fix] src/digitalocean_mcp/client.py (whole file — no logging anywhere in `src/`) — The tech design's "Non-functional / Observability" section (docs/tickets/PRD-21338.md §Tech design) states: "structured logs include ticket-relevant fields (tool name, DigitalOcean operation, app/deployment id when present, outcome, latency) and explicitly never include the token header value or full response bodies." This is also a mandatory SOP requirement (`vendor-mcp-development-sop.md` §6 "日志与可观测性": "用结构化日志... 记录：工具名、入参摘要（脱敏）、你的 API 路径与状态码、耗时、错误 code", and the §14 delivery checklist "日志与敏感信息" row "结构化日志带 request-id"). `grep -rn "log\|Log" src/` (excluding the unrelated `get_logs` DigitalOcean tool) finds zero uses of Python's `logging` module or any structured logger anywhere in `src/digitalocean_mcp/` — `client.py`, `middleware.py`, `tools/_shared.py`, and `server.py` have no logging calls at all. Once this connector is live on INT, there is no way to see which tool was called, what DigitalOcean API path/status it hit, how long it took, or what error code it failed with — the design's own stated non-functional requirement is not implemented, and the Self-test section does not flag this as a known/deliberate gap (it is presented as done). Fix: add a structured logger (e.g. stdlib `logging` with a JSON/key=value formatter) that emits one record per outbound DigitalOcean call with request-id/tool name/path/status/latency/error code, verify it never logs the `Authorization` header or `X-DigitalOcean-Api-Token` value or raw response bodies, and note the addition in Self-test.
